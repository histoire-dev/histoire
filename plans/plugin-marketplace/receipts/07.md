## Deviations

1. **Blocking shared store ownership:** `APP/stores/marketplace.ts` already owns first-page loading and watches query/filter/sort/preferences. It calls the raw client immediately. Starting a second request owner from browse components would duplicate work. This unowned file was left unchanged. The acceptance regression observes **three requests instead of one** for `a`, `ax`, `axe` across Vue ticks. Actual store/client injection of the new adapter passes the same assertion.

   Required orchestrator change in that store:

   ```ts
   import { createDebouncedCatalogClient } from '../components/marketplace/browse/catalog-client.js'

   // Inside createMarketplaceStore, replace its current client assignment:
   const client = createDebouncedCatalogClient(options.client ?? marketplaceClient)
   ```

   Existing store controllers already pass abort signals on query replacement, close and disposal, and preserve `page` during loading. The adapter handles both delayed and active cancellation. It is idempotent when an embedding injects an already wrapped client. Existing shell/owned screen fixtures that assume requests exist after only `nextTick()` must then await the 150 ms contract before inspecting/replying. Keep the failing acceptance case; do not turn it into an expected failure.

2. **Blocking collection contract gap:** locked `CatalogQuery.filters` has category/framework/publisher/adds but no collection identity. Catalog service truncates each Discover collection to 12 members. Implemented a bounded, workbench-local view of the returned membership for “See all” and “Try”, rather than guessing a category or searching for a collection title. Search/facet/sort changes leave that snapshot for ordinary results. This does **not** establish full collection filtering/pagination or sorting within a collection.

   Required orchestrator changes: add `filters.collection?: string` to shared DTO, validate it in `NODE/marketplace/catalog/validation.ts`, filter validated manifest memberships before pagination/facets in catalog service/facet code, and apply the same filter in `APP/util/marketplace-client.ts` static reads. Then adapt owned `selectCollection`, entries/count rendering and active-filter detection to use the server-filtered pages instead of bounded snapshots. Add a collection with more than 12 members as integration coverage. No shared contract/server/client files changed here.

3. **Collection suggestions:** All responses have no `discover` payload. Browse retains the last Discover collections for subsequent empty-search suggestions. Preferences changing clear cached suggestions; a fresh response can populate them. Opening All directly offers suggestions only when the response supplies groups; no collection titles or memberships are fabricated.

4. Added three small modules (`CatalogState.vue`, `labels.ts`, `plugin-actions.ts`) plus the reusable adapter inside the owned directory to share actual behavior and keep files small. Source specs use the real default Vue Vitest config and existing virtual-module alias; no extra Vitest config or module mocks.
