## Watcher decision

`configurationWatchInputs` watches Histoire/Vite candidates and imported local modules. It does **not** normally add package.json or lockfiles. `snapshotLocalModules` excludes node_modules. However, a config can explicitly import package.json, making package-manager writes watched inputs. Core rejects such automation without host lease support.

Config writes themselves always need coordinated restart suppression. Merely holding an in-process coordinator lease is insufficient for CLI installs: the marketplace runs in a child, while the proxy coordinator lives in its parent. A late chokidar notification can also arrive after release, so “ask” needs reconciliation of the exact saved revision, not merely dropping callbacks already queued.

## Deviations

1. **Blocking, unowned host integration:** `MarketplaceRegistrar(ctx, channel, isActive)` exposes no parent restart authority. Implemented `bindJobLifecycle(ctx, lifecycle)` and source coordinator `holdRestarts`, but did not fabricate an HTTP origin, mutate Context or add unowned IPC. Orchestrator must bridge lease acquisition/release and explicit restart through host owners before channel registration. Relevant files are `packages/histoire-dev-proxy/src/index.ts`, `src/process/child.ts`, `src/protocol.ts`, `packages/histoire/src/node/commands/dev-child.ts`, and SDK hosting/controller integration under `NODE/runtime/`. This bridge must reconcile the exact config revision before releasing “ask”, suppress late watcher echoes, preserve unrelated config causes, and trigger package-only restarts. Live `job-start` currently returns private `unavailable` with manual instructions until binding exists. Do not enable it with a no-op lease.
2. **Blocking, unowned browser contribution evidence:** `Context.workbenchPlugins` only exposes resolved entry paths and descriptor IDs. It contains no browser registration acknowledgement or contribution inventory. `load-check.ts` checks those server-side facts and returns `contributions: []`; it never copies manifest `adds` or invents registered UI. Actual entry registration, contribution IDs/labels, and post-install spotlight require an extension-host report and transport integration outside ownership. Until then the full happy-path acceptance gate is unmet.
3. **Unowned planner default-config seam:** `getPlanStore(ctx)` passes `ctx.configFile` directly, but normal `createContext` can leave it undefined for auto-discovered configs. The jobs handler uses `ctx.pluginToggle?.file ?? ctx.configFile`; planner should similarly resolve its standalone config before store creation. Orchestrator must fix `NODE/marketplace/changes/handlers.ts` / planner initialization. Tests use the real supported explicit-config path, rather than mutating Context to hide this issue.
4. **Acknowledgement/retention contract:** locked events have no job acknowledgement. Latest terminal receipt expires lazily on `current`; per-job files avoid deleting a successor during expiration. Superseded receipt files still need a directory TTL sweep or a real acknowledgement protocol before retention is complete. The tiny latest pointer can remain after its target expires. No shared DTO/event edited.
5. Receipts live under guarded `.histoire/marketplace`, alongside existing config backups/cache conventions, instead of the older architecture paragraph's `node_modules/.cache/...`; package-manager failure can replace node_modules, so recovery must survive there independently. Each private file uses mode 0600. Snapshots cap at 10 MiB raw bytes; reads cap at 16 MiB serialized bytes.
6. Reused `@histoire/cli/sanitize` for terminal escape stripping. A dedicated package-manager spawn adapter is necessary because existing ACP process launcher has one-second escalation, incompatible with this slice's three-second requirement.
7. Peer suggestions fetch exact metadata only with community consent in runner; pure advice adapter accepts registry options for local fixture tests. No registry query occurs in rollback tests with community disabled. Official-only fallback advice beyond bundled metadata remains unimplemented.
