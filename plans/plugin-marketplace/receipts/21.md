## Deviations

1. **Blocking real pnpm behavior.** `pnpm add -D -w histoire-plugin-interop@3.0.0` exits zero despite incompatible direct `vite@6.1.0`, even with strict peer settings enabled in both project `.npmrc`, workspace YAML and environment. Real output includes `WARN Issues with peer dependencies found` and `unmet peer vite@^7: found 6.1.0`. pnpm 10.33.2's installed `dist/pnpm.cjs` explicitly sets `opts.strictPeerDependencies = false` when the operation is not installs-only. Production currently reports this job as succeeded. Required peer rejection/rollback/advice assertion stays failing; no expected behavior weakened and no fake manager added. Orchestrator must add explicit peer validation to `marketplace/jobs/execute.ts` and/or adjust `changes/package-manager.ts`, then rerun the harness. Adding only the strict flag cannot defeat pnpm's unconditional reset.
2. **Default command isolation.** Added `HISTOIRE_MARKETPLACE_INTEROP=1` opt-in instead of editing unowned package Vitest configuration. Without opt-in, suite registers one visibly skipped acceptance test and performs no manager discovery/install. With opt-in, each unavailable manager has six named skipped cases.
3. **Real repair proof beyond peer rejection.** npm rejects incompatible peers before installed mutation; pnpm does not reject them. Additional invalid-factory install succeeds at package step, fails real config loading and must remove installed package through dependency repair. This independently rejects a no-op repair process.
4. **Native CJS cache limitation.** Exploratory same-process update from valid 1.0.0 to invalid CJS 2.1.0 unexpectedly completed successfully, consistent with cached native factory remaining available in repeated config loads. No config-loader code changed. Final migration case proves installed version, reviewed config migration and successor inventory/load result; it does not certify replacement CJS factory execution. Repair case starts without that package so real invalid factory executes. Orchestrator should investigate `config/load.ts` / generation process boundaries separately.
5. **Sandbox process behavior.** Sandboxed child Node processes exit zero with empty output. Verified same child prints normally outside sandbox. Real manager checks and fault probe ran with approved sandbox escalation; npm/pnpm presence is asserted, preventing sandbox behavior from becoming an all-skipped green acceptance run.
