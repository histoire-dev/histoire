### Public handoff for slice 11

`store.postInstall.value` is `undefined` or:

```ts
interface PostInstall {
  jobId: string
  pluginId: string
  openPane?: string
}
```

- `jobId` is admitted server receipt identity. `pluginId` is npm package id (`@histoire/plugin-a11y`), not extension descriptor id (`a11y`).
- `openPane` is selected manifest rail-pane **text/label**, currently first advertised rail pane, captured only when “Open <pane> after install” is checked. It is not a trusted contribution id. Resolve npm identity through installed inventory, then actual browser extension registrations; never infer loaded contribution from manifest alone.
- Session key `_histoire-marketplace-job:${import.meta.env.BASE_URL}` retains job id, exact reviewed `ChangeRequest` (including restart policy/options), optional destination and restart-request marker. Fresh store restores destination immediately, and matching server receipt restores wizard intent/open state. Different receipt discards stale local intent. Restart-request marker prevents duplicate automatic requests across reload.
- Consume destination only when `store.job.value.jobId === postInstall.jobId`, server job succeeded, load step completed, and actual browser contribution exists. Call `store.acknowledgePostInstall(jobId)` after handling/dismissal; wrong receipt id cannot clear newer intent. This removes persisted handoff without deleting server job.
- `store.startJob(planId, hash, reviewedRequest, openPane?, options?)` records admitted review and owns listener until workbench disposal. `store.restartJob(job?)` handles explicit continue/restart; `store.restarting` and `store.restartError` expose feedback. Current mutable preferences cannot overwrite an admitted policy.
