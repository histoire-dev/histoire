# Plan review — 2026-10-02

Scope: [embeddable SDK](embeddable-sdk/README.md) (planning only) and [MCP server](mcp-server/README.md) (existing implementation; [evidence](mcp-server/evidence.md) records completed gates). Checked for internal consistency, consistency between the two packs, feasibility against the working tree in this repository (source read where a plan assumes an API), security of the embedding bridge, missing tests, and the Starpad's needs ([factory requirements](factory-requirements.md), H-ids). Status per finding: **Applied** (plan edited in this pass) or **Open**.

## Verdict

Initial review required alignment with existing MCP services, an explicit bridge trust boundary, deploy-time configuration for built books, and factory host features (Node capture, globals, layout geometry, storage-independent embedding). Those plan changes are applied, including protocol negotiation tests and the public API method-signature lint fix. Follow-up review found four contract/ownership gaps; repairs below are applied to documentation. No SDK or MCP slice 16 implementation is claimed by these edits. SvelteKit nested-base proof remains a separate follow-up (M3).

## Top changes

1. **Protocol version negotiation** (S7). Contract and tests applied in public-api.md and slices 07/16. Hosts and books pinned to different Histoire versions need version-range negotiation and a conformance cell.
2. **Trust boundary and cross-origin opt-ins** (S3, S4). Applied. Story code shares the book origin with the bridge wrappers; the parent must bound and validate everything, and remote parents must not trigger editor launches or server test runs by default.
3. **Deploy-time origins and framing headers** (S5, S6). Applied. Built books must accept new parent origins without rebuild; Histoire servers send `frame-ancestors`.
4. **Rebase on landed MCP modules and align error codes** (S1, S2). Applied.
5. **Node capture with deterministic defaults** (S13, M1, M2). Applied as plans (SDK slice 13, MCP slice 16).

## Findings: embeddable SDK

- **S1 — Stale against landed code.** Major. Slices 02/03 and [coordination](embeddable-sdk/coordination.md) say "add" modules that now exist: `runtime/{controller,start,cleanup,config-watchers,execution-service}.ts`, `mcp/project/{runtime-catalog,content,content-index}.ts`, `node/story-source.ts`, `@histoire/shared` `preview-url.ts`, `mcp/browser/*`. [validation.md](embeddable-sdk/validation.md) "Recorded baseline" lists 20 failing tests while [MCP evidence](mcp-server/evidence.md#baseline) records the same 391 tests passing, and MCP work already modified `run-tests-harness.ts`. Applied: coordination "Update 2026-10-02", architecture "Current checkout" note, slice 02 owned files, slice 03 owned files, validation baseline note.
- **S2 — Error code collision.** Major. SDK `SOURCE_UNAVAILABLE` meant "book unreachable" while MCP `SOURCE_UNAVAILABLE` means "raw source unavailable"; SDK used `SOURCE_CONTENT_UNAVAILABLE` for the MCP meaning. Applied: [public-api.md](embeddable-sdk/public-api.md) "Errors" now uses `BOOK_UNAVAILABLE` and `SOURCE_UNAVAILABLE` with the MCP meaning; coordination records the rule.
- **S3 — Trust domain unstated.** Major, security. Surface wrapper, bridge wrapper, and story sandbox share the book origin, so story code can drive the wrapper and forge any child-side message on the bound port. Validation was specified at child dispatch, not as parent-side bounds (size, rate). Applied: public-api.md "Trust boundary"; slice 07 tests 7 and step 10.
- **S4 — Risky commands exposed cross-origin.** Major, security. `openInEditor` (launches a local editor) and server-mode tests (run project code with side effects) were reachable from any allowed remote origin. Applied: off unless `embed.allowOpenInEditor` / `embed.allowServerTests`; public-api.md "Trust boundary"; slice 07 test 8.
- **S5 — No framing protection.** Major, security. Nothing in Histoire sets `frame-ancestors` (comment in [host-messaging.ts](../packages/histoire/src/node/virtual/preview-runtime/host-messaging.ts)); slice 16 only documented it. Applied: dev and Node servers send the header when embed is enabled; public-api.md "Source documents…", slice 06 test 8 and step 11, slice 16 step 4.
- **S6 — Allowed origins baked at build.** Major. Static descriptors and Node artifacts fix `allowedOrigins` at build, which breaks build-once-promote across environments. Applied: deploy-time override (`histoire-embed-origins.json`, `HISTOIRE_EMBED_ORIGINS`), fail closed; public-api.md, slice 06 test 7.
- **S7 — Protocol negotiation has no owner.** Major. Original pack left negotiation outside slice 01 without assigning implementation. Applied: public-api.md "Common identities" owns range negotiation and the compatibility window; slice 07 test 10 covers host range 1–2 against book 1 and book 3; slice 16 test 10 owns the version-skew conformance cell.
- **S8 — Nuxt plugin assumptions.** Major, feasibility. [Nuxt plugin](../packages/histoire-plugin-nuxt/src/index.ts) calls `loadNuxt` without `cwd` (breaks explicit root from an unrelated cwd), hard-codes runtime `app.baseURL: '/'` (nested base unproven; MCP framework test skips the base check for nuxt4), and declares peer `nuxt ^3.0.0-rc.11` while the example runs Nuxt 4.2. Applied: slice 02 owned files + test 6; slice 15 example and peer fix; slice 16 test 8; MCP slice 16 test 4.
- **S9 — Embedded appearance depends on storage.** Major. Sandbox dark mode comes from storage-backed `useDark` ([dark.ts](../packages/histoire-app/src/app/util/dark.ts)); third-party iframes get partitioned or blocked storage. Applied: settings only over the bridge in embedded documents; public-api.md "Settings…", slice 07 test 9, slice 08 test 9 and step 9a.
- **S10 — Lint error in public-api.md.** Minor. Line 50 `unmount(): Promise<void>` fails `ts/method-signature-style` and blocks unfiltered repo lint (recorded in MCP README). Applied.
- **S11 — No performance budgets.** Minor. Each session creates a bridge iframe plus a surface and a sandbox iframe; hosts with several live previews need numbers. Applied: validation.md "Performance budgets", slice 16 test 9.
- **S12 — Missing tests.** Minor. No tests for hostile same-origin story traffic, storage-blocked iframes, `logEvent` attribution end to end, per-variant setup isolation (incl. Nuxt), Nuxt UI/Tailwind v4. Applied: slice 07 tests 7–9, slice 08 tests 7–10, slice 12 test 7, slice 15 test 7, slice 16 test 8.
- **S13 — Screenshot non-goal blocks hosts.** Minor. "SDK screenshot API" was a non-goal everywhere, yet hosts need headless capture from Node and `sandboxUrl` cannot be driven by an external harness (M1). Applied: Node `captureScreenshot` in public-api.md "Node SDK" and slice 13; browser SDK still has no screenshot API.
- **S14 — Settings type location.** Nit. `PreviewSettings` lives in histoire-app `types.ts`, not shared; public-api.md now says to move the wire-safe type into protocol once.

- **M2 — Screenshots are not deterministic.** Major for visual baselines. Fonts plus one frame only; no animation/transition/caret control, fixed DPR, reduced motion, timezone, or locale. Applied: [slice 16](mcp-server/16-capture-determinism-and-globals.md) (planned).
- **M3 — Nested base unproven for Nuxt 4 and SvelteKit.** Minor. [frameworks.spec.ts](../packages/histoire/src/node/__tests__/mcp/integration/frameworks.spec.ts) line 26 skips the base assertion for both. Applied for Nuxt (slice 16 test 4); SvelteKit stays open (no factory need).
- **M4 — Unauthenticated loopback dev MCP on shared hosts.** Minor, security. Any process in the same network namespace can start screenshots and tests. ## Follow-up gap repair

Applied to plans only; implementation evidence belongs to each slice's acceptance gate.

1. **Built preview capture had no route/catalog/cleanup owner.** [Public contract](embeddable-sdk/public-api.md#built-preview-capture-ownership) now defines additive built capture metadata, immutable target lookup, nonce routing before static fallback, source identity, restart/close invalidation, and output-write protection. [SDK 03](embeddable-sdk/03-catalog-and-content-services.md) owns built metadata/reader, [04](embeddable-sdk/04-node-sdk-and-middleware-hosting.md) owns preview host lifecycle, and [13](embeddable-sdk/13-test-execution-and-cancellation.md) consumes both. Tests cover copied static output with embedding disabled, nested bases, expired routes, cancellation, and no live dev catalog.
2. **DPR input and result dimensions disagreed.** [MCP 16](mcp-server/16-capture-determinism-and-globals.md) assigns strict inputs to tool-schema.ts and PNG results to operation-schema.ts, propagates options through dev/deploy adapters, and checks decoded pixels against CSS viewport multiplied by DPR. [Contracts](mcp-server/contracts.md#planned-additive-changes-slice-16) define scaled output bounds independently of the 4 MiB byte limit. Maximum-DPR proof includes retention and polling.
3. **Grid geometry described the outer frame, not variants.** [Runtime geometry](embeddable-sdk/public-api.md#runtime-geometry) now exposes structured per-variant entries, clipping, selected-entry alias, and complete replacement notifications. [SDK 08](embeddable-sdk/08-preview-and-grid-runtime-ownership.md) owns cell registration, nested-frame coordinate mapping, scroll/resize/lazy updates, and stale-document cleanup.
4. **Wire limits conflicted and could recurse through cyclic state.** [Wire size and traversal limits](embeddable-sdk/public-api.md#wire-size-and-traversal-limits) now define command-specific cap precedence, JSON byte accounting versus cycle-safe graph accounting, traversal bounds, and typed overflow/stale-data behavior. [SDK 01](embeddable-sdk/01-contracts-packages-and-baseline.md) owns one portable helper; [07](embeddable-sdk/07-cross-origin-bridge-and-iframe-surfaces.md) tests large catalogs, cyclic state, limits, and correlated failures. No competing serializer is introduced.

## Questions

1. **Protocol compatibility window.** How long must a host SDK accept older books? Recommended: N and N-1 for at least six months after N ships (S7).
2. **Nuxt grid isolation.** The Nuxt plugin boots one Nuxt app per sandbox document, so grid variants may share it. Recommended: document the limit; per-variant fixture state lives on each Vue app via `provide`, not on the Nuxt app.
3. **frame-ancestors with embed disabled.** Recommended: leave headers unchanged so existing users who iframe their book do not break.
4. **MCP screenshot pixel changes.** Deterministic defaults change v1 output. Recommended: accept; no pixel stability was promised.
5. **Host channels in v1?** Recommended: no; ship after slice 16 as capability-gated additive protocol (SDK slice 17).
6. **Static origin override request.** It adds one same-origin fetch before handshake. Recommended: accept; treat 404 as absent, anything else invalid as fail closed.
7. **SvelteKit nested base.** Recommended: separate follow-up outside slice 16.
