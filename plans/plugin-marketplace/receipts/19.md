## Delivered behavior

- `resolveNpmConfig(root, registryUrl?)` reads user npmrc, declared workspace npmrc, project npmrc and supported `npm_config_*` environment values in increasing precedence. Lowercase environment names override uppercase aliases. Unrelated ancestors and global npmrc are excluded.
- `registryFor(id?)` selects scoped or default registry. Search uses default; packuments use package scope. Explicit `RegistryOptions.registryUrl` overrides all routes for fixtures.
- Bearer tokens, pre-encoded Basic `_auth`, and username/base64-password pairs remain server-only. `${ENV}` expansion supports all recognized values; unresolved credentials remain unset and mask lower-priority values for that key.
- Authorization uses longest matching host/port/path prefix. Sibling paths, other ports and other hosts receive no credentials. Exact repeated-slash path boundaries are preserved. Redirects remain forbidden.
- Invalid HTTP header values are discarded before Fetch can quote them in errors. Registry URLs reject userinfo, query strings, fragments and non-HTTP protocols. HTTP failures include status and registry host without response body or authorization.
- `registryPackumentUrl(config, id)` supplies one credential-free key for fetches, read-only plugin planning and migration history. Existing update and suggestion readers inherit routing/auth through the shared client.
- Tests verify cache filenames/content stay unchanged when credentials are removed; cache contents and successful/failed channel replies exclude the fixture token. Planning/migration cache reads make no requests or writes.
