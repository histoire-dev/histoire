## Deviations

1. **Planner hook shape.** Existing `computePlan` hard-codes `migrate: true` as manual, and `createPlanStore` recomputes privately at admission. Neither file is owned. The authorized `changes/handlers.ts` hook therefore wraps the existing store with `withMigrations`; it calls `planMigrations` inside the adapter for migrated updates. Base capabilities retain their original hash privately; public hash additionally binds installed version, ordered ops and exact migrated source. No unowned planner/store/job edit was needed. Direct consumers of raw `createPlanStore` retain slice 04 behavior; production handlers and job runner share `getPlanStore`, which now supports migrations.
2. **Additive update-detail protocol.** Frozen `PluginDetail`/detail request cannot request version history. Added `histoire:ui:marketplace-update-detail` and `…-result` in owned handler/client. Request is `{ requestId, id, prefs }`; result reuses `{ requestId, detail: PluginDetail } | { requestId, error }`. `detail.latest` and `installed.update` identify compatible target; `releaseNotes` concatenate intervening notes newest first; `manifest.migrations` contains selected operations for checkbox availability. Planner independently re-reads original version manifests. Local declaration merging and transport adapter keep feature functional without shared/client edits. Shared owner may centralize these event declarations in `histoire-shared/src/types/ui-marketplace.ts` and expose a wrapper in `APP/util/marketplace-client.ts`; those files remain untouched.
3. **Official-only history limit.** Existing bundled index stores one current manifest per official package. With community off, updates remain offline and display bundled notes/migrations; omitted historical releases cannot be recovered. Guaranteeing every historical release offline requires official-index/contract owners to bundle per-version history in `NODE/marketplace/catalog/official.json` and its generator/DTO seam. Community-enabled complete version history is covered by real registry integration. No registry consent bypass or invented notes were introduced.
4. **Pin downgrade warning.** This slice applies migrations only to `kind: 'update'` with `migrate: true`; downgrade/equal migration selection is empty and explicit migrated downgrades warn. Existing `kind: 'pin'` flow has no downgrade warning. Adding that warning belongs in unowned `changes/planner.ts` or settings pin owner; no pin migration or unowned edit was added.
5. **Existing typecheck limits.** Default Node/app checks read stale shared dist declarations. Spec-inclusive app graph retains four unowned plugin-kit/protocol errors. Source-alias Node/app graphs and ordinary Vue package check pass. No compiler settings or unowned sources were changed to hide errors.
