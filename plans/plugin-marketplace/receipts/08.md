Latest version can use `plugin.compatible.reason`; other disabled menu items show “Incompatible with this project”. Exact per-version explanations would require an optional reason field in unowned shared types plus catalog mapping. Those files were not changed.
2. **No typed not-found error:** live catalog and static client both emit exact message `Plugin not found`, with different error codes. Detail recognizes that existing message and uses the shared empty state. A dedicated not-found code requires an orchestrator contract change; other errors retain retryable shared error state.
3. **Native-dialog menu placement:** `WorkbenchPanelAction` hardcodes the provider overlay outside the marketplace dialog. Its split menu would be inert in the native top layer. Detail retains that component for the primary CTA and composes its own adjacent HstButton/BasePopover with an explicit local overlay target. This uses existing public primitives and changes no unowned code. A future optional overlay-target prop on the shared action could consolidate the split wrapper.
4. **Spec-inclusive typecheck:** existing SDK fixture imports protocol source through `utils/embed/catalog.ts`. App's non-strict-null configuration then reports `histoire-protocol/src/helpers/meta.ts:83` (`TS2322`). Owned implementation source and native package typechecks pass. Unowned protocol/configuration files were not edited. A trial strict-null override exposed unrelated app diagnostics and was removed; checks were not weakened to hide the error.
