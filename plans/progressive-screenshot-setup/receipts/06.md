# Slice 06 receipt — Node deployment portability

## Changes

- Node deployment now reads `HISTOIRE_BROWSER_SOURCE` and `HISTOIRE_BROWSER_EXECUTABLE_PATH` from target environment. Source defaults to `auto`; supported explicit sources are validated through the shared browser policy. Relative executable paths resolve against the copied artifact root, and path validation errors do not echo the supplied path.
- Deployment creates one setup owner from that target policy and shares it through Node screenshot, inspection, and compiled-test sessions. Injected `launch` remains authoritative and bypasses policy parsing and owner creation. Setup discovery is metadata-only before listener startup; unavailable setup disables capture capabilities while catalog/content stay available.
- Shutdown marks deployment inactive, drains operations, closes the setup owner, then releases host, transport, and listener while preserving cleanup failures.
- Build metadata uses shared launch-free driver identity resolution. Generated artifacts pin only the selected optional `playwright` or `playwright-core` package and version. The legacy Playwright-only packaging input remains supported. Custom build executable paths are not written to manifest, package metadata, or bundled server.
- The standalone bundle allowlist admits only `config/browser.ts` from the new policy path; project config loaders and development runtime imports remain rejected.
